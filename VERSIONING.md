# Руководство по версионированию мода ComplexityAnalyzer

Этот проект использует поэтапную систему релизов на основе **Semantic Versioning 2.0.0**.
**Главное правило: Номера версий всегда увеличиваются и никогда не сбрасываются.**

---

## 🚀 **Процесс разработки и версионирования**

### **Этап 1: Alpha (Альфа-версии)**
*Стадия активной разработки. Добавляются новые фичи, проводятся эксперименты. Сборки могут быть нестабильными.*

**Правила:**
- Версии имеют суффикс `-alpha`.
- Для исправления бага увеличивается **ПАТЧ** (третья цифра).
- Для добавления новой фичи увеличивается **МИНОР** (вторая цифра).

**Пример жизненного цикла Alpha:**
1.  **`0.1.0-alpha`** (Первая версия с базовым анализом)
2.  **`0.1.1-alpha`** (Исправлен баг в экспорте)
3.  **`0.1.2-alpha`** (Оптимизировано кеширование)
4.  **`0.2.0-alpha`** (Добавлена новая фича: AI ассистент)
5.  **`0.3.0-alpha`** (Добавлена новая фича: JEI Phantom)

---

### **Этап 2: Beta (Бета-версии)**
*Стадия стабилизации. Новые крупные фичи не добавляются. Основная работа — поиск и исправление багов, полировка существующего функционала.*

**Правила:**
- Версии имеют суффикс `-beta`.
- Номер версии для первой беты **должен быть больше**, чем у последней альфы.
- Последующие бета-версии увеличивают **ПАТЧ** или **МИНОР**.

**Пример жизненного цикла Beta (начинается после `0.3.0-alpha`):**
1.  **`0.4.0-beta`** (Первая бета-версия, номер `0.4.0` > `0.3.0`)
2.  **`0.4.1-beta`** (Исправлены баги, найденные тестерами)
3.  **`0.5.0-beta`** (Проведен рефакторинг GeoScanner, минорное изменение)
4.  **`0.5.1-beta`** (Еще исправления)

---

### **Этап 3: Stable 0.x.x ("Неполный релиз")**
*Версии, которые достаточно стабильны для широкого использования, но проект все еще находится в начальной стадии разработки до версии `1.0.0`.*

**Правила:**
- Версии не имеют суффикса.
- Номер версии для первого такого релиза **должен быть больше**, чем у последней беты.

**Пример жизненного цикла Stable 0.x.x (начинается после `0.6.0-beta`):**
1.  **`0.7.0`** (Первый публичный стабильный релиз до 1.0.0)
2.  **`0.8.0`** (Добавлена новая небольшая фича, например, команда `/complexity tps`)
3.  **`0.8.1`** (Исправлен баг в команде `/complexity tps`)

---

### **Этап 4: Stable 1.x.x (Официальный релиз)**
*Проект считается полностью стабильным. Публичный API зафиксирован. Любые ломающие изменения требуют увеличения МАЖОРНОЙ версии.*

**Пример:**
1.  **`1.0.0`** (Первый официальный стабильный релиз)
2.  **`1.0.1`** (Исправление бага после релиза)
3.  **`1.1.0`** (Добавлена новая фича с сохранением обратной совместимости)
4.  **`2.0.0`** (Выпущено ломающее изменение, например, изменена структура конфига)

---

## 📋 **Краткая шпаргалка для `gradle.properties`**

| Твой шаг                             | Пример последней версии | Следующая версия |
|--------------------------------------|-------------------------|------------------|
| Начинаешь разработку                 | -                       | `0.1.0-alpha`    |
| Исправил баг в альфе                 | `0.1.0-alpha`           | `0.1.1-alpha`    |
| Добавил фичу в альфе                 | `0.1.2-alpha`           | `0.2.0-alpha`    |
| Переход из альфы в бету              | `0.3.0-alpha`           | `0.4.0-beta`     |
| Исправил баг в бете                  | `0.4.0-beta`            | `0.4.1-beta`     |
| Переход из беты в "стабильную 0.x.x" | `0.6.0-beta`            | `0.7.0`          |
| Добавил фичу в "стабильной 0.x.x"    | `0.7.0`                 | `0.8.0`          |
| Исправил баг в "стабильной 0.x.x"    | `0.8.0`                 | `0.8.1`          |
| Готов к первому официальному релизу  | `0.9.5`                 | `1.0.0`          |
